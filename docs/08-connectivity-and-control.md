# Подключения и управляющий канал

> Статус: временное рабочее решение. Схема будет уточняться после проверки реального оборудования и протокола LoRa-станции.

## Назначение документа

Документ фиксирует предварительную схему подключения полётного контроллера, Arduino-амперметра и возможных маршрутов управляющих команд.

Проверка физического пульта, радиоприёмника и RC-протокола не входит в задачи приложения. Оператор проверяет наличие связи вручную, двигая стики. Приложение может показать получаемые значения `RC_CHANNELS`, но это является информационной индикацией, а не отдельным автоматическим тестом пульта.

## Обязательные подключения

### Полётный контроллер

Полётный контроллер подключается к компьютеру через отдельный USB-порт:

```text
USB №1 → MAVLink → Flight Controller
```

Основное MAVLink-соединение используется для:

- heartbeat и определения состояния контроллера;
- получения телеметрии;
- чтения и подтверждаемой записи параметров;
- получения значений RC-каналов;
- отправки разрешённых управляющих команд;
- выполнения централизованной процедуры abort.

### Arduino-амперметр

Кастомный амперметр на Arduino подключается через второй независимый USB Serial-порт:

```text
USB №2 → Serial → Arduino-амперметр
```

Амперметр является источником эталонных измерений и не используется как управляющий канал. Формат и версия его протокола будут описаны отдельно после проверки текущей прошивки Arduino.

## Маршруты управления

Приложение должно поддерживать выбор одного активного маршрута управляющих MAVLink-команд:

```text
1. Основное соединение контроллера
   Приложение → USB №1 → Flight Controller

2. LoRa
   Приложение → отдельный USB Serial → наземная LoRa-станция → борт → Flight Controller

3. Локальная сеть
   Приложение → Ethernet/Wi-Fi → UDP/TCP → companion computer → Flight Controller
```

Для сетевого варианта ноутбук может раздавать локальную Wi-Fi-сеть. Выход в публичный интернет для этого не обязателен. Companion computer принимает MAVLink по UDP или TCP и передаёт его полётному контроллеру по UART или USB.

Точный вариант LoRa-интеграции зависит от того, предоставляет ли наземная станция прозрачный MAVLink Serial или собственный протокол. До проверки оборудования LoRa считается отдельным транспортным адаптером.

## Эмуляция действий пульта

Приложение эмулирует необходимые действия оператора на уровне MAVLink. Предварительно рассматриваются:

- `RC_CHANNELS_OVERRIDE` — управление отдельными RC-каналами;
- `MANUAL_CONTROL` — нормализованные положения основных стиков;
- `MAV_CMD_DO_MOTOR_TEST` — специализированное управление моторами во время стендового теста.

Конкретный механизм выбирается сценарием испытания и возможностями целевой версии ArduPilot. Для калибровки тока предпочтителен motor test, если он поддерживает требуемый режим работы. RC override применяется, когда необходимо воспроизвести изменение конкретных каналов.

Эмуляция через MAVLink не проверяет физический передатчик, радиоприёмник, SBUS, CRSF или вход `RCIN`. Создание отдельного USB–SBUS/CRSF-эмулятора не планируется.

## Выбор активного маршрута

В каждый момент времени только один маршрут имеет право отправлять управляющие команды. Одновременная отправка через USB контроллера, LoRa и сеть запрещена.

Предварительный интерфейс выбора:

```text
Полётный контроллер:  USB Serial / подключён
Амперметр:            USB Serial / подключён

Маршрут управления:
  • через соединение контроллера
  ○ через LoRa
  ○ через Ethernet/Wi-Fi
```

Переключение маршрута должно быть явной операцией:

1. прекратить отправку по старому маршруту;
2. освободить активные RC override-каналы;
3. вернуть управляющее состояние к безопасному;
4. проверить heartbeat и доступность нового маршрута;
5. получить подтверждение оператора, если тест уже был подготовлен к запуску;
6. разрешить команды через новый маршрут.

Автоматическое переключение управляющего маршрута в первой версии не используется.

## Индикация физического пульта

Если ArduPilot передаёт `RC_CHANNELS`, приложение может показывать:

- текущие значения каналов;
- время последнего сообщения;
- признак наличия или отсутствия свежих RC-данных.

Изменение значений при ручном движении стиков считается достаточной операторской проверкой связи с пультом. Приложение не делает вывод о качестве или надёжности радиоканала.

## Обязательные safety-правила

- UI не отправляет MAVLink-команды напрямую;
- управляющие команды проходят через Application Core и safety-проверки;
- каждая длительная команда имеет timeout;
- значения каналов и нагрузки ограничиваются профилем стенда;
- при abort освобождаются все RC override-каналы;
- потеря heartbeat или управляющего маршрута прекращает тест;
- отсутствие ответа не считается успешной командой;
- переключение маршрута запрещено во время активного управляющего воздействия;
- события подключения, команды и причины остановки записываются в audit log.

## Открытые вопросы

- модель и протокол наземной и бортовой LoRa-станций;
- является ли LoRa-соединение прозрачным MAVLink-каналом;
- способ подключения companion computer к полётному контроллеру;
- UDP или TCP для первого сетевого прототипа;
- формат и частота данных текущей прошивки Arduino-амперметра;
- целевая версия ArduPilot и поддерживаемый режим motor test;
- необходимость показывать все RC-каналы или только назначенные сценарием.
